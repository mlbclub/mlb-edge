# V9 robust champion/challenger selection

The V8 selector could replace the baseline using a single validation period.
V9 defaults to the reconstructed V5 core and promotes a challenger only after
passing predeclared gates across three chronological validation periods.
These rules were not tuned against 2026 results.

## Feature contract

`robust_selection.V5_BASES` explicitly reconstructs the 162 numeric difference
features generated by `features.py` at `2ccb87b`. The classifier also gets the
72 home/away level features and month/Elo probability from `train.py` at
`a153e82`: 236 classifier inputs in total. The list was checked against the
actual V5 artifact at `c76ae7f`. Missing core columns raise an error instead of
silently changing the champion. Future `diff_*` columns cannot enter it.

The existing 11 candidates (core plus 10 challengers) add only named feature
families. Each candidate also uses its corresponding explicit run-model
features: the champion has 326. This closes the indirect path by which V7
context could otherwise enter the moneyline ensemble through run probabilities.
The same selected run models continue to provide totals; consequently totals
also use the selected feature families, rather than always using all V7 context.
No separate totals-engine experiment is introduced in this change.

## Chronology and scoring

Only rows with both season and calendar year in 2024–2025 enter fitting and
selection. Validation windows are July–December 2024, January–June 2025, and
July–December 2025. Every fold trains on strictly earlier dates. Calibration
and ensemble-weight learning are nested within that training data; nested
splits keep each UTC day together. Ensemble weights retain the V5 log-loss
objective. Candidate selection uses the hit-rate-focused policy below.

Each fold needs at least 800 training games, 300 validation games, 30 predictions
at >=60% confidence, and 100 at >=55%. Three valid folds and at least 150 pooled
>=60% predictions are required for both champion and challenger before promotion.
The 800-game training floor accommodates the 932 eligible games available before
July 2024; it was chosen from data availability, not prediction outcomes.

Accuracy lower bounds use the 95% Wilson interval (z=1.96). Fold and pooled
reports include counts, correct predictions, accuracy, lower bounds, AUC,
log loss, and overall accuracy. The composite score is:

```
score = 4 * LCB60 + LCB55 + 0.3 * AUC + 0.2 * accuracy - 0.2 * log_loss
robust_score = pooled_score + worst_fold_LCB60 - 2 * std(fold_accuracy60)
```

Promotion requires all of:

- Robust score at least 0.025 above the champion.
- Pooled >=60% lower bound at least 0.01 above the champion.
- At least ceil(75% × 3) = 3 folds improving >=60% lower bound by 0.01.
- No fold losing more than 0.02 in >=60% accuracy.
- Pooled log loss increasing by no more than 0.005, with AUC and overall
  accuracy each declining by no more than 0.005.

Among passing challengers, the highest robust score wins. Ties, insufficient
samples, or missing folds keep the champion. The bounds are conservative
selection heuristics, not a claim of statistical significance after multiple
candidate comparisons or a guarantee of future hit rate.

2026 is evaluation-only. A small 2026 sample no longer causes an 82% fallback
split that could contaminate selection. An absent holdout is explicitly reported;
a single-class holdout has no AUC. No threshold filters raw predictions and no
NO BET rule is added. Recommendation and UI code remain unchanged.

## Artifacts and operation

`train()` writes `data/robust_ablation_report.csv` with candidate/fold rows,
pooled summaries, feature lists, learned weights, date boundaries, policy,
promotion reasons and selected flags. It also writes summary rows to the legacy
`ablation_report.csv`. The bundle retains all V8 keys, adds
`selection_diagnostics`, and uses version `sports-lab-v9-robust-champion`.
Both training predictions and unmodified `live.py` read the persisted
`win_features`, `run_features` and ensemble weights.

`run_pipeline.py` verifies that the report exists. The workflow runs regression
tests before training, stages the new report with the model, and allows six
hours for nested fits. It still runs on its existing daily schedule or manual
`workflow_dispatch`; pushing code alone does not start this workflow.

Local verification: ten regression tests, the existing odds smoke test,
syntax compilation, and a full-capacity core fit on the 932 real games before
July 2024 followed by eight prediction/live-parity checks. The local smoke fit
uses fixed ensemble weights and is not a full 11-candidate training run.
Full retraining is required to generate production diagnostics and replace the
existing model artifact. Test reports use temporary directories and are not
published as real ablation results.
